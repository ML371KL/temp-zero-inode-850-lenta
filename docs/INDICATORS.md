# Слой опережающих индикаторов «Ленты»

Слой отвечает на третий вопрос проекта: что покажет ближайший отчёт — раньше рынка — и насколько этому можно верить. Он собирает публичные источники, ведёт поквартальный нау-каст маржи, пишет неизменяемый журнал прогнозов и честно зачитывает их против наивных эталонов. **К цене нау-каст не подключён**: он показывает, что сделает с оценкой факт (экран «Ближайший отчёт»), и копит зачёт для правила допуска. Код — `indicators/`; эксплуатация тактов — `ops/README.md`; поля выпуска — `docs/DASHBOARD.md`.

## Кварталы, а не полугодия (D2, D15)

Модель полугодовая, а «Лента» отчитывается поквартально. Нау-каст и журнал ведут **ближайший неотчитавшийся квартал** (с 30.09.2026 — 3 кв. 2026, отчёт ≈29.10.2026, окно 26.10–03.11), а маржа его полугодия (2026H2) пишется рядом: она идёт в правило A-P2u и в таблицу «что даст отчёт» (`docs/MODEL.md` §4.3, §16).

- **Периоды** (`indicators/periods.py`): идентификаторы `2026Q3`, `2026H2`, `2026FY`; границы, сдвиги, «тот же период год назад», квартал ↔ полугодие, ключ книги квартала (`Q3`). Первый прогнозный квартал — `FIRST_FORECAST_QUARTER` = 2026Q3.
- **Отчёт как событие** (`periods.report_id`): `lenta.q1_ГГГГ`, `lenta.h1_ГГГГ` (2 кв. и 1П — МСФО 6М), `lenta.q3_ГГГГ`; у 4 кв./2П/года **два события** — `lenta.q4_ГГГГ_ops` (выручка, операционные результаты ≈февраль) и `lenta.fyГГГГ` (маржа, годовой МСФО ≈март). Имена совпадают с id календаря `data/calendar.json`.
- **Календарь** (`indicators/calendar.py`, `data/calendar.json`, схема `lenta-calendar-v1`): центр окна (`when`) — для горизонтов и обратного отсчёта, **конец окна** — для сторожа журнала «окно закрылось, а факт не внесён». Нет события в календаре — запасное правило лагов после конца периода (`REPORT_LAG_DAYS`: 1–3 кв. 30/35 дней, операционные 4 кв. 38/43, годовые 85/90 — по датам релизов 2024–2026). Календарь книги сильнее правила; дату объявляет компания, правится она в `data/calendar.json`.

## Сборщики (`indicators/sources.py`)

Реестр `COLLECTORS` и его дисциплина: каждый сборщик стоит в расписании (`DAILY`/`WEEKLY`), классы — ниже. Оба такта сервера (утренний `collect` ≈04:20 UTC и вечерний `daily` ≈17:25 UTC по будням) зовут один реестр `DAILY`: второй проход дня ловит отчёт, вышедший в 10:00 МСК (раскрытие и датабук), а сборщики раз в сутки второй раз источник не трогают. `WEEKLY` пуст.

| Сборщик | Источник | Класс | Ряды |
|---|---|---|---|
| `moex_quote` | MOEX ISS, режим TQBR: LENT, X5, MGNT (последняя сделка) | **критический** | `moex.price.{LENT,X5,MGNT}` — LENT — живая цена выпуска, аналоги — справочно на одной базе |
| `moex_curve` | ISS: бескупонная кривая `zcyc` и ОФЗ-ИН 52002–52005 (TQOB) | **критический** | `moex.zcyc.*`, `moex.ofz_in.*` — наблюдение: диагностика устаревания книги и входы пересборки миров |
| `moex_security` | ISS: карточка LENT (`LISTLEVEL`, `ISSUESIZE`) | раз в сутки | `moex.security.LENT.listlevel`, `.issuesize`; смена после даты книги — плашка и совещательный гейт `security_change` («пересмотреть g») |
| `cbr_key_rate` | ЦБ, SOAP `DailyInfo.asmx`, `KeyRate` | обычный | `cbr.key_rate` посуточно (самолечащаяся глубина) |
| `bonds` | ISS: поиск выпусков по ИНН ООО «Лента» и ООО «О'КЕЙ» → фильтр по кодам эмитентов {5997, 4867} → доска TQCB | справочный | `lenta.bond.<ISIN>.price` (доля номинала), `.yield`, `lenta.bonds.traded`; в примечании — погашение и пут-оферты (Б1Р8 — 09.02.2027, Б1Р6 — 17.03.2027, они же в календаре) |
| `lenta_disclosure` | лента существенных фактов www.lentagroup.ru (JSON `App = {…}` платформы Zebra) + тела сообщений | защищённый (не ротируется), восполнимый | `lenta.disclosure.latest`, `.new` (новые id с прошлого снимка), `.<класс>` (по дню публикации), `.events` (по дате события п. 1.7) |
| `lenta_databook` | страница публикаций www.lentagroup.ru → ссылка на датабук → xlsx | **невосполнимый**, защищённый | `lenta.databook.published` (день релиза), `lenta.databook.new_version` (сигнал «вышел отчёт»), `lenta.databook.q.<имя>` — квартальный P&L IAS 17 с винтажами |
| `trudvsem_vacancies` | API «Работы России» (`opendata.trudvsem.ru`) по ИНН юрлиц группы | раз в сутки, защищённый, «может ничего не разобрать» | `lenta.vacancies.total.<ИНН>`, `.total`, `.with_salary`; после сбора — справочный индекс вилок `lenta.salary.*` |

- **Классы** (`sources.py`): `CRITICAL` = {`moex_quote`, `moex_curve`} — без них выпуск теряет смысл: отказ останавливает суточный такт на сборе (код 1), на витрине остаётся прежний выпуск; `IRRECOVERABLE` = {`lenta_databook`} — новая версия датабука заменяет старую на странице, не скачанная до замены пропала: отказ — тревога кодом 8 в конце такта, вечерний такт повторяет попытку (`--retry`); `ONCE_A_DAY` = {`moex_security`, `trudvsem_vacancies`} (причины — `ONCE_A_DAY_REASONS`; признак — маркер «ок» дня, а не «уже лежит на диске»); `MAY_PARSE_NOTHING` = {`trudvsem_vacancies`} — пустой ответ до месяца устойчивой работы с сервера — вопрос доступа, а не тревога; перевод в невосполнимые — решением владельца после месяца устойчивой работы. `store.PROTECTED_SOURCES` = {`lenta_databook`, `trudvsem_vacancies`, `lenta_disclosure`} — их сырое ротация не трогает никогда.
- **Тихий день биржи.** ISS сбрасывает таблицу котировок в 07:00 МСК; в выходной и в биржевой праздник к утреннему такту сделок ещё нет — `LAST` пуст, `NUMTRADES` = 0 у всех бумаг запроса. Это не отказ: сборщик `moex_quote` называет причину сам (`Collected.idle`), статус — «ок: торгов сегодня ещё не было…», точек нет, такт идёт дальше, живая цена — последняя принятая (`model/live.py`, не старше 7 дней). Отказом остаётся всё остальное: пустая сделка при ненулевом числе сделок, ответ без строки LENT, без колонки `NUMTRADES`, пустая таблица.
- **Лента раскрытия.** Новизна — по множеству id (id из ссылки против последнего снимка ленты; первый снимок «новых» не объявляет). Дата события — п. 1.7 текста («Дата наступления события»), а не день публикации. Классы по названию (порядок важен: оферта раньше сделки): `coupon`, `redemption`, `offer`, `placement`, `programme`, `rating`, `results`, `dividends`, `own_shares`, `listing`, `record_date`, `board`, `ma`, `material`, `other`; «существенное влияние» и «прочее» уточняются по тексту (сначала заголовок пресс-релиза, затем весь текст). Классы тревоги `DISCLOSURE_ALARM_KINDS` = (`ma`, `own_shares`, `dividends`, `listing`, `offer`, `placement`) — строки «СОБЫТИЕ» в журнале такта и плашка корпоративных событий на витрине (7 дней). **Блок подписанта и контакты пресс-релиза вырезаются до записи**, почты и телефоны — страховкой везде; тело ложится очищенным текстом, sha256 — от очищенных байтов. В архив идёт список ленты, и только когда он изменился; тела — новые id первыми, история — окно 400 дней, не больше 3 тел за такт.
- **Датабук** — лист «Financials quarterly»: блок «IAS 17», метки «1Q 2020…», строки выручки (итого, розница, форматы, опт), валовой прибыли, персонала, аренды, EBITDAR, EBITDA, чистых процентов (расход пишется со знаком «плюс»), прибыли до налога и чистой прибыли; маржа EBITDA считается. Первое вхождение метки (ниже лист повторяет метки в SG&A и ДДС). Пустая ячейка — нет числа, не ноль. Сломанный файл — `DatabookLayoutError` (после сохранения файла). Каждая новая версия — `databook_<sha12>.xlsx` с метой (sha256, ссылка, имя, название релиза); перепроверка той же ссылки — раз в 7 дней. Сам датабук — первичка: в репозиторий не кладётся, в фикстурах — выписка листа.
- **«Работа России»** — задокументированное исключение из правила «сырое до разбора»: на диск ложится ответ, прошедший **белый список полей** (id, даты, вилка, валюта, должность, профессия, график, число мест, регион, реквизиты работодателя, специализация, ссылка); контакты, обязанности, требования и адреса отбрасываются; sha256 — от очищенных байтов; нечитаемый ответ не хранится вовсе. Юрлица — ООО «Лента», ООО «О'КЕЙ», ООО «Элемент-Трейд» («Монетка»), ООО «Дрогери Ритейл» («Улыбка радуги»), ИНН — `indicators/issuer.py` (сверены по ISS и карточкам работодателей; по ЕГРЮЛ — открытый вопрос). Бюджет — не больше 6 страниц на ИНН и 12 за такт (сервер отвечает 10–22 с на страницу).
- **Индекс вилок** (`indicators/salary_index.py`, общий модуль 850oa) — цепной по совпадающим вакансиям (границы вилки раздельно, усечённое среднее отношений, ошибка — бутстрепом по регионам) и ячеечный «роль × регион» рядом; ряд справочный, к цене и к нау-касту не подключён — только через правило допуска, как любое новое слагаемое. Охват «Работы России» у «Ленты» мал; индекс видит предложение, а не выплаты.
- **Эмитент** (`indicators/issuer.py`, необязательный `data/issuer.json`): тикер LENT, префикс рядов `lenta.`, аналоги X5 и MGNT, сайт раскрытия, коды эмитентов облигаций, юрлица «Работы России». Витрина и выпуск читают имя и тикер отсюда, а не из литералов.

## Вежливость

- Один HTTP-клиент на стандартной библиотеке (`indicators/http.py`): свой User-Agent `tzi-850-lenta/1.0 (+https://github.com/ML371KL/temp-zero-inode-850-lenta)`, пауза 2 с между запросами к одному хосту, без параллельности, тайм-аут 30 с, повтор только на сетевых сбоях, 408/425/429 и 5xx.
- Запросов за такт — единицы на источник (котировки — 1, кривая — 2, облигации — 3, раскрытие — 1 + не больше 3 тел, датабук — 1 и файл только при новой ссылке или раз в 7 дней, «Работа России» — не больше 12 страниц в сутки).
- **Не собираются** (не предлагать заново): hh.ru, e-disclosure, lenta.com, rabota.lenta.com и monetka.ru (за Qrator), Чек Индекс, СберИндекс, цены с полки, архив публикаций lentagroup.ru по годам. Защиту от ботов не обходить. Источники, банящие по IP, с сервера не опрашивать никогда: бан утащит все панели владельца.
- Тесты в сеть не ходят: сборщики проверяются на обрезанных ответах источников (`tests/fixtures/`, описание — `tests/fixtures/SOURCES.md`; подписант и контакты заменены заглушками, тест ловит почты, телефоны, поля контактов и «И. О. Фамилия»).

## Хранилище (`indicators/store.py`)

- **Сырой архив**: `raw/<источник>/<дата получения>/…` и `.meta.json` (адрес, время, sha256); ответы больше 32 КБ — gzip. Ротация (`prune_raw`) снимает дни незащищённых источников старше окна `keep_days` (400 дней); защищённые не трогает. Потолок состояния `STATE_CEILING_BYTES` — 2 ГБ (команда `health`; прирост за 7 дней — журнал `state_size.log`).
- **Ряды** `series/<id>.json` с винтажами — что было известно на дату (PIT); одинаковое значение (до 1e-12 относительно) новой версией не пишется.
- **Здоровье** (`python -m indicators.collect health`): живые ряды `VITAL_SERIES` — ключевая (не старше 10 дней), котировка LENT и 10-летний узел кривой (5 дней); невосполнимый ряд `lenta.databook.published` — не старше 130 дней (самый длинный промежуток между отчётами ≈85 дней). Нарушение — код 1 команды и тревога такта.
- Отчёт сборщиков `collector_report.json` читает сборка выпуска: отказавшие сборщики попадают в `live.degraded` и плашку деградации.

## Нау-каст (`indicators/nowcast.py`, `indicators/quarterly.py`)

- **`lenta-margin-v1`**: маржа ближайшего квартала = ожидание модели = маржа полугодия ядра (цели режимов, взвешенные вероятностями книги, и затухающее отклонение внесённого факта; средняя по сетке) + квартальная поправка книги `margin.quarter_offset_pp`. Ошибка — `margin.quarter_sigma_pp`, если книга её заведёт, иначе σ A-P2u·√2 (верхняя оценка: на истории отношение RMSE лучших эталонов квартал/полугодие ≈1,17). Слагаемых сверх ожидания нет — отклонение от ожидания 0; `connected_to_price = False`.
- **`lenta-revenue-v1`**: выручка квартала = выручка полугодия ядра × доля квартала внутри полугодия (`revenue.quarter_share`); ошибки выручки книга не задаёт.
- Ожидание квартала считает ядро: `model/quarters.py::expected_quarter(result, book, quarter_id)` на сетке `build_grid` (`indicators/quarterly.py` его зовёт).
- Рядом — **маржа полугодия** (`half_value` и её σ): идёт в журнал отдельной записью `2026H2` и в правило A-P2u (`apply_to_book` подаёт полугодие).
- **«Какая маржа 2П следует из факта 3 кв.»** (`quarterly.implied_half_margin`, выпуск `nowcast.implied_half`): при полной персистентности m(2П) = m(3 кв.) − o(Q3); без персистентности m(2П) = s₃·m(3 кв.) + s₄·E[m(4 кв.)]; плюс «сюрприз» против ожидания; таблица — по строкам «что даст отчёт». После `record-actual` за 2026Q3 выпуск сам печатает следствие для 2П.
- **Гайденс** (`quarterly.guidance_half_margin`): нужная маржа 2П = (g_min·(R₁ + R₂) − E₁)/R₂ на отчётном 1П (≈7,8 % при гайденсе ≥7 % за 2026); эталон квартала 2П — нужная маржа 2П + поправка квартала.
- **Канал процентов** (`indicators/interest.py`): чистые проценты квартала — посуточное начисление по реестру долга `data/facts/debt_register.json` (плавающие транши — ключевая + спред, фиксированные — купоны) минус доход на кассу; заявленная точность ±8 % (`collect.INTEREST_ACCURACY`); главный эталон — прошлый квартал × отношение средних ключевых ставок.

## Журнал прогнозов (`indicators/journal.py`)

- **SQLite в состоянии** (`$LENTA_STATE_DIR/indicators/journal.sqlite`), записи неизменяемы: правку и удаление запрещают триггеры; прогноз после факта или после конца окна отчёта — отказ; каждая запись несёт хэш входов и версию уравнения.
- **Событие** — квартальный отчёт; из периодов одного отчёта (4 кв./2П/год; 2 кв./1П) в зачёт идёт квартал. Величины — маржа EBITDA IAS 17 (`lenta.ebitda_margin_pre16`), выручка IAS 17 (`lenta.revenue_pre16`), чистые проценты (`lenta.net_interest`).
- **Горизонты** 90 / 45 / 15 дней до публикации; **зачёт — на 45** (≈11 дней до конца квартала, отчётов аналогов ещё нет). Эталоны берутся на тот же момент, что прогноз.
- **Зачёт 1 квартала — на фактическом горизонте** (`Journal.scored`, `journal.expected_scoring`; решение владельца 30.09.2026, `docs/DECISIONS.md`, запись 10). Слой переходит на квартал только после факта предыдущего, а маржа 4 кв. выходит годовым отчётом (≈26.03) — позже момента зачёта 1 кв. (45 дней до его отчёта, ≈15.03): прогноза на 45 дней у 1 кв. быть не может. В зачёт идёт первый прогноз 1 кв. после внесения факта 4 кв. — ближайший суточный такт, ≈34–36 дней до отчёта; эталоны прежние и берутся на тот же день (модель и эталоны видят факт 4 кв. на одну дату). Строка табло несёт правило (`scoring_rule`), фактический горизонт (`scoring_horizon_days`) и причину (`note`). Правило общее: так засчитывается любой квартал, чей предыдущий отчитался позже момента зачёта; если же предыдущий отчёт вышел вовремя, а прогноз появился поздно (факт внесли с опозданием), зачёта нет. Факт 4 кв. вносить в день выхода годового отчёта: каждый день задержки укорачивает горизонт 1 кв.
- **День публикации факта исправляется** новой строкой с тем же числом (`record-actual --reported-on`): от него меряются горизонты; без `--reported-on` день берётся из прежней записи периода, у первой записи — сегодня.
- **Эталоны маржи:** `yoy_plus_shift` — главный: m(t−4) + [m(t−1) − m(t−5)] (тот же квартал год назад + сдвиг прошлого квартала г/г); `seasonal_naive`; `last_period`; `mean_of_year`; `model_expectation` — ожидание модели без индикаторов (**обязательный**: без него событие не зачитывается); `guidance` — гайденс компании (маржа за год → маржа 2П и её кварталов). **Выручки:** `yoy_growth_carried` — главный (тот же квартал год назад × рост прошлого квартала г/г), `seasonal_naive`. **Процентов:** `previous_period_scaled_by_rates` (прошлый квартал × отношение средних ставок).
- Эталоны из закрытых периодов **замораживаются** при первой записи (`FROZEN_BENCHMARKS`); ожидание модели и гайденс — ряды во времени (`UPDATING_BENCHMARKS`). Такт нау-каста замороженные эталоны не пересчитывает (иначе в день отчёта новый датабук ронял бы такт тревогой).
- **Поправка на периметр** (`indicators/perimeter.py`): список разрывов — «Монетка» 01.10.2023, «Улыбка радуги» 01.12.2024, «Молния» 24.06.2025, «Реми» 03.12.2025, «Дом Лента» 01.01.2026 (поэтапно в 1 кв.), «О'КЕЙ» 02.06.2026. Сравнение периода с опорными периодами эталона сломано, если консолидация попадает в (начало самого раннего опорного периода; конец периода]. Для главного эталона «О'КЕЙ» ломает 2026Q2–2027Q3 (2027Q3 — потому что сдвиг прошлого квартала сравнивает 2027Q2 с 2026Q2, где «О'КЕЙ» только за июнь). Проформы по кварталам нет, поэтому такие кварталы печатаются на табло с причиной, но **в счёт допуска не идут** (`admission_excluded`). Следующая сделка вносится данными: `data/facts/perimeter_breaks.json` (схема `lenta-perimeter-breaks-v1`).
- **Факт** — только командой `record-actual` на сервере (боевой журнал): квартал — маржа и выручка квартального релиза (1–3 кв.), полугодие и год — годового МСФО; у 4 кв. выручка — операционными результатами, маржа — годовым отчётом, журнал сам разводит их по событиям. Проверяются величина, период (не раньше 2026Q3 и не позже текущего квартала), коридор значения (маржа — доля: 7,15 % это 0,0715; выручка и проценты — млрд ₽ за период) и день публикации (не в будущем). Пока факт не внесён, после конца окна отчёта такт нау-каста каждый раз даёт тревогу.

### Правило допуска

Правило (строка выпуска `nowcast.admission.<цель>.rule`, `journal.admission_rule_text`; числа — решение владельца, не подгонка):

> допуск к правилу A-P2u — решение владельца, не раньше чем после 8 отчётных кварталов вне выборки (без кварталов с разрывом периметра главного эталона) и при отношении MSE уравнения к лучшему эталону, включая ожидание модели без индикаторов, не больше 0,8; понижение до справочного — если на последних 4 отчётах отношение больше 1,0; в зачёт идёт прогноз за 45 дней до отчёта, а у квартала, чей предыдущий квартал отчитался позже этого момента (1 кв.: маржа 4 кв. выходит годовым отчётом), — первый прогноз после факта предыдущего, на фактическом горизонте

- Считаются только отчёты текущей версии уравнения (`lenta-margin-v1`): смена формулы — новая версия и обнуление счёта. Автоматического подключения к цене нет.
- Симуляция при n = 8 (ошибки нормальны, корреляция с эталоном 0,5 / 0,9): уравнение без умения проходит порог 0,8 в 25–36 % случаев, на 20 % точнее эталона — в 64–75 %; против обязательного эталона «ожидание модели» пустое уравнение не проходит никогда. Квартальные ошибки автокоррелированы — эффективное n меньше восьми.
- **Календарь допуска** (`nowcast.admission`: `countable`, `short_horizon_ahead`, `broken_ahead`): кварталы 2026Q3–2027Q3 исключены (разрывы периметра «Молния», «Реми», «Дом Лента», «О'КЕЙ»), поэтому первый засчитываемый квартал — 2027Q4; восемь засчитываемых — 2027Q4–2029Q3, из них 2028Q1 и 2029Q1 — на фактическом горизонте ≈35 дней; решение — не раньше 2029Q3 (отчёт ≈октябрь 2029). Календарь сверяется с посуточной симуляцией планировщика на настоящем журнале (`tests/test_journal_scoring.py`). Статус — выпуск `nowcast.admission` (зачтено 0 из 8 на 06.10.2026) и экран «Ближайший отчёт», карточка «До отчёта».

## Запуск

```bash
python -m indicators.collect collect        # утренний такт: весь реестр (= daily)
python -m indicators.collect daily          # ежедневные сборщики; --retry — повтор невосполнимых
python -m indicators.collect nowcast        # прогноз ближайшего квартала + запись в журнал
python -m indicators.collect status         # что собрано, свежесть, объём, допуск
python -m indicators.collect health         # живые ряды и объём состояния (код 1 — тревога)
python -m indicators.collect salary-index   # пересчёт справочного индекса вилок
python -m indicators.retro [каталог фактов] # таблица ретро-проверки
# только на сервере, в боевой журнал (факт неснимаем):
python -m indicators.collect record-actual --target lenta.ebitda_margin_pre16 --period 2026Q3 \
    --value <доля> --reported-on <день публикации> --source "Лента, 3 кв. 2026"
```

Состояние — `LENTA_STATE_DIR` (на ноутбуке по умолчанию `var/`). Такты ходят в живые источники: с ноутбука без нужды не запускать — это второй за сутки обход (вежливость выше). Коды выхода: 0 — собрано; 1 — отказал критический источник, выпуска не будет; 3 (`ALARM_EXIT`) — работа выполнена, но отказал невосполнимый источник или нарушена дисциплина журнала (такт доводится до конца и кончается тревогой; юнит — кодом 8, `ops/README.md`, раздел 4). Проба доставки тревоги — `--simulate-failure <имя>` (без обращения к источнику).
