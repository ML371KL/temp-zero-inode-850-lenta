# Модель: правила ядра под книгу «Ленты»

Документ описывает **правила** ядра (`model/`), которые читают книгу допущений `data/assumptions/assumptions.yaml`. Чисел книги здесь нет: их значения, основания и цену ошибки держит книга (`ASSUMPTIONS-BOOK.md`), происхождение — журнал версии (`V1.0-CHANGES.md`) и доказательные листы. Всё, что не названо ниже, — как у модели-предшественника 850oa (книга 1.6): APV, один мир ставок на клетку, распределение вместо точки, полоса A-V9 по суждениям книги, обратный DCF для печатаемой медианы.

## 1. Схема расчёта

- **Клетка** = мир ставок (N / H / M) × режим маржи (стресс / дно / частичная / полная интеграция) × уровень capex (low / base / high): 36 клеток (`model/grid.py`). Клетка — полугодовой проход 2026H2–2036H2 и терминал (`model/core.py::run_cell`).
- **Слои**: аналитические веса миров, веса, вменённые рынком облигаций, нейтральный мир M; V0 слоя = E[EV], D = E[требования] (`model/grid.py`).
- **Цена** — внутренняя стоимость max(V0 − D, 0)·(1 − g)/акции по каждому слою (`model/mapping.py`, D4); ползунок λ сдвигает точку между слоями.
- **Книга** — закрытая схема (`model/book_schema.py`): незнакомый ключ — отказ; правила книги проверяет `model/book.py::validate_book` при загрузке (`BookError`). Ядро — чистая функция книги: диск не читает.
- **Проба** `python -B -m model.book_results --fast` — выпуск на книге (сетка, слои, точка, сценарии, гейты) без полосы; полные таблицы — `python -B -m model.book_results` → `results.json` (с `environment`: интерпретатор и платформа; канон — Python 3.12) и `run_output.txt`; числа в текстах — `python -B ops/tools/render_numbers.py`. Справочные наборы таблиц (не суждения книги) — `data/assumptions/results_spec.yaml`: контрольные наблюдения A-P2u и строки «что оправдывает рыночную цену»; конец строки к рынку выбирает расчёт по знаку разрыва точки и цены (`direction`).

## 2. Выручка по сегментам (D3)

Выручка группы = сумма сегментов `revenue.segments` по строкам отчётности. LFL группы полугодия = (1 + чек)·(1 + трафик) − 1; чек = k × продовольственный ИПЦ мира + s (A-R1). Печатается тот же LFL (`StepRow.lfl`: строки и годы `results.json`, витрина), а не сумма чека и трафика.

| Режим | Правило полугодия p (к тому же полугодию год назад, p − 2) |
|---|---|
| `yoy` (сеть) | R(p) = R(p−2) · A_eff(p)/A_eff(p−2) · (1 + LFL группы + `lfl_offset` сегмента) |
| `level` («Дом Лента») | R(p) = A_eff(p) · плотность(p) · индекс ИПЦ мира от якоря (полугодовое наращение) |
| `revenue` (опт) | R(p) = R(p−2) · (1 + LFL группы + `growth`) — прибавка к LFL группы (B14) |

- **Эффективная площадь** — правило 850oa по сегменту: когорты открытий дозревают по общей кривой `maturity_curve`, новая площадь входит с плотностью d (`new_space_density`), закрываемая уходит с продуктивностью cp (`closed_productivity`).
- **История эффективной площади** выводится тем же правилом назад от конца якоря по закрытиям истории `closed_area_hist` и плотным когортам `new_area_dense_cohorts` (E12; `model/core.py::effective_history`); записанная история сверяется при загрузке (`model/book.py::check_effective_area_history`).
- **Основа выручки** сегмента по полугодиям — `reported` / `pro_forma` / `estimate`; у `reported` ошибка 0, у расчёта и проформы — `revenue_se` (B13). У сегмента `level` база истории не требуется; `null` ≠ 0.
- **Кварталы** (D2): `revenue.quarter_share` — доли кварталов **внутри полугодия** (пара = 1); `margin.quarter_offset_pp` — поправки кварталов, взвешенно по выручке внутри каждого полугодия равные нулю (допуск 1e-12; `model/book.py::quarter_rules`). Квартальный слой — ожидание для нау-каста и журнала (`model/quarters.py`), в оценку не входит.

## 3. Маржа

Цель режима — траектория по годам и LT; отклонение от цели затухает AR(1) с ρ; обновление вероятностей режимов по наблюдениям полугодий — правило A-P2u (Калман, наблюдение с se, предел сдвига). Ключ цели `"2026H1"` — якорь; сезонность — `seasonal_h1_pp` с `season_from_period`, одна функция для прогноза и правдоподобия (`model/core.py::margin_season`, C21). Наблюдение якоря — `facts.anchor.margin_pro_forma` с se; в `observations` — только факты полугодовых отчётов.

## 4. Capex, D&A

Поддерживающий capex — доля выручки по уровню; физическая доля растёт с площадью и ценами. Capex открытия — `growth_capex_per_m2` сегмента × открытия. **Инфраструктура** — `infra_capex_per_net_m2` × Σ по сегментам max(0, открыто − закрыто) (D23: закрытия одного сегмента не гасят открытия другого). Интеграционный capex — траектория книги. Амортизация — линейная по когортам (база D&A якоря за срок службы, каждая когорта — своим сроком).

- **Дата удельных цен** открытий, инфраструктуры и замещающих открытий терминала — `capex.unit_price_basis` (`model/book.py::unit_price_basis`). `anchor_average` (по умолчанию, 850oa) — средние цены полугодия якоря: индекс цен полугодия p — индекс ИПЦ ядра Π_{q≤p}(1 + h_q), h — полугодовая ставка ИПЦ мира. `anchor_end` — цены конца полугодия якоря: индекс ядра, делённый на (1 + h_p)^0,5 (в терминальном полугодии — на (1 + h_LT)^0,5). Перезаякоривание переводит цены множителем (1 + h) закрытого полугодия при обеих конвенциях. Плотность сегментов `level` — всегда в средних ценах полугодия якоря.
- **Физическая часть поддерживающего capex по форматам и когортам** — `capex.physical` (`model/book.py::physical_rule`, `model/core.py::PhysicalArea`). Без блока — правило 850oa: физическая доля s ключа A-K1 идёт за невзвешенной физической площадью × индекс цен / выручка 12 месяцев к базе x₀ первого полугодия. С блоком площадь сегмента делится на эталонную часть min(A_f, ref_f) (сеть, на которой посчитан A-K1) и запас новой площади max(0, A_f − ref_f), хранимый когортами по полугодию прироста (убыль снимается с младших когорт). Веса: зрелый м² формата — `steady_per_m2` к среднему эталонной сети (у эталонной сети Σ вес·площадь = площадь), молодая когорта — `young_per_m2` (обслуживание и РЦ без реконструкций) до возраста цикла реконструкций формата на уровне capex клетки (`reconstruction_cycle_years`). Поддерживающий capex(p) = выручка·A-K1(p)·(1 − s) + выручка·s·(индекс/выручка 12 мес.)/x₀·[A-K1(p)·эталонная часть + A-K1(последнего полугодия)·новая площадь] (середины полугодий — полусуммы концов); x₀ — эталонная сеть в ценах и выручке первого прогнозного полугодия. Терминал — стационар по взвешенной площади: Σ w_f·A_f на выходе. Перезаякоривание переносит `reference_area`, запас новой площади на конец каждого закрытого полугодия (`young_stock`) и x₀ (`maintenance_area_base`).

## 5. Оборотный капитал и перекат на дату оценки

- **Старт** — ОК якоря по балансу `nwc.anchor_level` (D27; ядро принимает ровно один из `anchor_level` / `nwc_pct_start`): ось июньского излишка меняет долю, а не стартовый уровень (`model/core.py::nwc_start_level`).
- ОК приобретённого периметра сверх условий «Ленты» — `nwc.acquired_path`, доля выручки года.
- **Перекат ЧД на дату оценки** (A9): ЧД(дата) = ЧД(якорь) − [d·(FCFF + ΔОК + щит − проценты) − w·ΔОК] текущего полугодия; EV берёт остаток того же полугодия с тем же w. d — доля полугодия по дням; w — доля изменения ОК по квартальным весам `nwc.quarter_share` (внутри квартала — по дням; `model/core.py::nwc_quarter_weight`). Один вес в ЧД и EV — поток не теряется и не считается дважды.

## 6. Налог

Налог без рычага — на EBITDA − налоговая амортизация + постоянные разницы; щит = налог без рычага − фактический налог (две корзины α, пул убытков с лимитом зачёта до года полного зачёта).
- **Ускоренная налоговая амортизация** (D25): доля `tax.capex_tax_premium_share` capex каждой когорты вычитается сразу, остальное — линейно; база налога уменьшается на премия·(capex − D&A). В терминале налоговая D&A = премия·capex + (1 − премия)·D&A, статьи, растущие с ценами, считаются с той же премией.
- **Невычитаемая часть D&A якоря** (`tax.nondeductible_da_anchor`, амортизация торговых марок ППА): налоговая D&A = премия·capex + (1 − премия)·(учётная D&A − невычитаемая); невычитаемая часть убывает вместе с базой D&A якоря — значение × max(0, 1 − (полугодий базы + i + 1)/(2·срок службы)) (`model/core.py::nondeductible_da`; та же функция — в инструменте перезаякоривания).
- **Запертые убытки приобретённых юрлиц** (D26): `tax.acquired_nol` {amount, usable_from, discount_rule {method: frozen_until_usable_from, haircut, locked_addback}}. До `usable_from` (присоединения) пул заморожен и растёт на `locked_addback`; в первом полугодии ≥ `usable_from` в общий пул входит (1 − haircut) накопленного.

## 7. Финансирование

- **Корзины ставок** (A10): `financing.rate_baskets` — доли всего основного долга; ставка корзины `{fixed: x}` или `{key_plus: спред}`, живёт по `until`; справедливая ставка корзины = своя (премия фиксированного долга — строкой моста, не второй раз). Новый долг — `fixed_share` по ОФЗ 3 года мира + спред и остаток по ключевой + спред (`model/core.py::basket_debt_rate`).
- **Дивидендная лестница — «платить верх ступени»** (решение ведущего по вопросу P2; `model/core.py::dividend_rule`). С года `dividends_from_year` в каждом полугодии: FCFE = max(ЧД(p−1) − ЧД до выплаты(p), 0); запас = max(0, L·EBITDA LTM − ЧД до выплаты); ступень — первая по возрастанию `max_leverage` с λ = ЧД до выплаты/EBITDA LTM < `max_leverage`; **D = min(max(запас, FCFE), payout_max·FCFE)** (`payout_max: null` — без предела; нет ступени — D = 0). Без ключа `dividend_ladder` — D = запас (правило 850oa). Следствие: между L и следующей ступенью выплачивается весь FCFE полугодия, поэтому сезонное высвобождение ОК во 2П уходит акционерам, а отток 1П и полугодия с отрицательным FCFE поднимают долг без обратного хода — рычаг пути дрейфует вверх до ступени, на которой потолок меньше 100 % FCFE.
- **Сроки выплаты лестницы** (решение ведущего F1; `financing.dividend_timing`, `model/core.py::run_cell`, `ladder_payout`). `annual_next_h1`: та же формула раз в год — FCFE года = FCFE 1П + FCFE 2П (в формулу — max(·, 0)), ступень и запас по ЧД и EBITDA LTM на 31.12, выплата в 1П следующего года, во 2П выплат нет; `dividends_from_year` — год первой выплаты. Год, 1П которого закрыт на якоре, начинается с факта `facts.anchor.fcfe_ytd` (при якоре на 2П — FCFE всего года, выплата в первом прогнозном полугодии); факт обязателен, когда выплата по году якоря в горизонте. Сезонный отток ОК 1П и приток 2П гасятся внутри года — рычаг конца года не дрейфует. Без ключа — правило полугодия выше.
- **ЧД порогов лестницы** (находка I1d, решение ведущего F1; `financing.dividend_net_debt_basis`). `reported`: λ и запас — по отчётному ЧД = модельный − (операционная касса(p) − операционная касса якоря); FCFE тот же. Перезаякоривание на ожидаемом пути тогда равно перекату бит в бит (`tests/test_reanchor.py`); инструмент переносит FCFE года (`fcfe_ytd`, факт `dividends_paid`). Без ключа — модельный ЧД (правило P2).
- **Неустойчивость**: издержки `valuation.distress.cost_pct_ev` × EV в клетке, где max ЧД/EBITDA по пути после даты оценки > порога или (при `credit_limit_trigger: true`) валовой долг выше лимита «долг + линии» (пара к щиту в терминале). Гейт `credit_lines` идёт за тем же суждением: при `credit_limit_trigger: false` (книга «Ленты» с F1 — номинальный лимит одной даты не ограничивает путь долга растущего бизнеса) путь против лимита — справка `checks.credit_lines` и флаг клетки на витрине.

## 8. Терминал

TV = Гордон_g(F − f_π) + Гордон_π(f_π): два полугодовых потока года после горизонта при нулевом чистом росте физической площади; замещающие открытия и физическая доля capex растут с ценами π (раздельный Гордон); годовая ставка щита и купона делится на полугодие по `valuation.terminal.half_rate_convention` (`simple` — r/2, `compound` — (1 + r)^0,5 − 1, как в явном периоде).

**База выручки терминала** (`valuation.terminal.revenue_base`, `model/core.py::terminal_revenue_factors`). `last_year` (по умолчанию, 850oa) — выручка полугодия последнего года × (1 + g). `exit_area` — выручка сегмента сети от эффективной площади НА ВЫХОДЕ горизонта, той же базы, что у capex терминала: A_ss = A_eff(конец) + Σ дозревания двух младших когорт до d·m_∞ − стационарная незрелость замещающих открытий (площадь × закрытия/2 × d × Σ_{a<k}(m_∞ − m_a)); множитель полугодия k = A_ss/A_eff,ср(то же полугодие последнего года) × (1 + τ_k·rot)/(1 + rot), rot = (d·m_∞ − cp)·закрытия (подъём ротации, который g уже содержит), τ = 0,25 / 0,75; множитель группы — средний по выручке сегментов; уровни ОК и операционной кассы на границе — тем же множителем (разовый сдвиг базы не капитализируется).

**Амортизация терминала в налоге** (`valuation.terminal.da_convention`, `model/core.py::terminal_da_runoff`). `annuity` (по умолчанию, 850oa) — налоговая D&A = премия·capex + (1 − премия)·аннуитет терминального capex (как если бы capex всегда рос темпом терминала). `cohort_runoff` — плюс поправка по полугодиям 2037+: фактические когорты capex явного периода и база D&A якоря (без её невычитаемой части) доамортизируются линейно, а из аннуитета вычитается та история capex, которую он предполагает (когорты capex_g/2·(1 + g)^(−(j+1)/2) и capex_π/2·(1 + π)^(−(j+1)/2)); ряд конечен (2L полугодий), поправка × τ·(1 − премия) приводится к концу горизонта в серединах полугодий при положительном налоге терминала.

**Рост терминала группы — средний рост сегментов с весами выручки последнего года** (решение ведущего по вопросу P2): g = Σ_s w_s·g_s, w_s = (R_s(последнее полугодие) + R_s(предыдущее)) / выручка группы тех же двух полугодий. g_s: `yoy` — LFL группы последнего полугодия + поправка сегмента; `level` — ИПЦ мира последнего полугодия; `revenue` — LFL группы + `growth`; у сегментов сети — подъём ротации (1 + g_s)·(1 + (d_s·m_∞ − cp_s)·закрытия_s) − 1. Чистый рост сети в g не входит. g ≥ r не считается (g = r − 1 б.п.). У одного сегмента — ровно его рост.

## 9. Гейты и оси

- **Гейты правдоподобия** (`model/checks.py`): коридоры `margin_range`, `capex_range`, `ev_ebitda` — данными в `gate_explanations.yaml` (поле `corridor`, `gate_corridors`), не литералами кода. **`guidance_gap`** — совещательный: масса клеток, у которых маржа года гайденса ниже `facts.guidance.ebitda_margin_min` (`check_guidance`, C20). У каждого сработавшего гейта — объяснение со сроком `valid_until`.
- **Оси полосы и строки чувствительности** (`model/uncertainty.py`, `model/engine.py::apply_override`): сдвиг (`shift_low/high`), значения по краям (`low/high`, в том числе словари по режимам), `kind: scale` — множитель траектории (`{"__scale__": f}`, LT-правила не трогаются), `kind: choice` — выбор конца. Каждый конец обязан исполняться ядром (тест `tests/test_book10_book.py`).
